## 한 줄 요약

원본 motion과 control sequence(스케치, 라벨, 오디오, 다른 motion) 사이의 cross-domain 매핑을 정의하거나 학습하지 않는다. 각 도메인 안의 patch 간 거리 구조만 맞추는 Gromov-Wasserstein optimal transport로 motion을 control에 정렬한다.

## 요약

motion을 다른 신호에 맞춰 시간 정렬하는 기존 방법은 수작업 매핑이나 대규모 paired/annotated 데이터로 학습한 매핑이 필요했다. MAMM은 원본 motion X와 control Y를 각각 겹치는 temporal patch로 나누고, 도메인 내부의 patch 간 거리 행렬만 계산한다. 그다음 "aligned motion X′의 거리 구조가 Y의 거리 구조와 닮고, 동시에 X′의 patch는 원본 X의 patch를 닮도록" fused semi-unbalanced Gromov-Wasserstein(FSUGW) loss를 최소화한다. 이때 transport plan T와 X′를 번갈아 최적화하고, coarse-to-fine으로 upsampling한다. X와 Y 사이의 거리는 전혀 계산하지 않기 때문에 도메인 종류와 상관없이 같은 알고리즘이 돌아간다. 학습 없이 한 번 생성하는 데 보통 10초 이내(RTX 4080)가 걸린다.

## 핵심 정리

- **Loss 구성**: Wasserstein loss L_W는 T를 통해 X′ patch를 대응되는 X patch에 가깝게 만들어 원본 동작의 품질을 유지한다. GW loss L_GW는 Y의 patch 쌍 거리와 X의 patch 쌍 거리 차이를 줄이도록 T를 정렬한다. 여기에 soft marginal(KL) 항을 더한 FSUGW 형태이며, solver는 Xu and Gould 2024의 projected mirror-descent를 따른다.
- **Patch 처리**: 원본 motion patch는 11프레임, stride 1. patch blending으로 X′를 다시 구성해 시간적 연속성을 확보한다. motion 표현은 GenMM처럼 root displacement와 joint rotation을 쓴다.
- **Coarse-to-fine**: GW 문제가 non-convex라서 초기화가 중요하다. 가장 거친 단계(최종 길이의 1/4)에서는 L_GW만으로 T를 초기화하고, 총 6단계를 거쳐 upsampling한다. motion-to-motion처럼 거리 행렬이 복잡한 경우 한 단계로만 풀면 실패한다고 한다.
- **제약**: soft keyframe(도메인 간 예시 patch 쌍. 위치 대신 의미로 지정하므로 "negative keyframe"처럼도 쓸 수 있음), hard keyframe(특정 시점 고정), infinite loop(GenMM 방식)을 지원한다.
- **응용**: sketch-to-motion(2D 곡선, 전용 UI), 1D waveform-to-motion(사인파 주파수로 동작 속도 조절), motion-by-numbers(one-hot 라벨 시퀀스), audio(40차원 MFCC, AIST 음악과 BEAT 음성), cross-skeletal motion-to-motion(Mixamo, Truebones 데이터).
- **파라미터**: α는 L_W와 L_GW 사이 균형(크면 control 영향 증가), λ는 원본 분포 유지 강도. 권장값은 α=0.8, λ=0.05.
- **평가**: 정량 비교 실험은 없고 정성 결과와 사용자 피드백(CS 학생 5명, 10분 튜토리얼과 15분 연습 후 영상 따라 만들기 과제를 모두 완료)뿐이다. 가장 긴 예시(594프레임 motion, 1441 MFCC 프레임 오디오)는 7초가 걸렸다.

## 흥미로운 점

- cross-domain 거리를 아예 쓰지 않고 "거리 구조만 같으면 대응된다"는 GW 관점이 깔끔하다. 하나의 프레임워크로 입력 종류를 모두 커버한다.
- 스케치 위치가 아니라 곡선의 전체 구조(큰 원은 큰 cyclic motion)에 맞춰지기 때문에, 같은 위치를 지나는 곡선이라도 시점에 따라 다른 pose가 나온다.
- GenMM 계열(학습 없는 patch 기반 생성)에 OT 정렬을 결합했다. Motion Matching이라는 이름이지만 runtime 검색이 아니라 offline 최적화라는 점이 특이하다.

## 한계와 의문

- 저자들이 밝힌 한계: control sequence 전체가 있어야 하므로 real-time 인터랙션이 불가능하다. 거리 기반이라 rigid transform과 대칭에 invariant하다(좌/우 스텝을 구분 못 함, keyframe으로 보정). 거리 정규화(max/mean) 설계가 어렵다. 거리 행렬 크기 때문에 수십만 프레임 데이터로 확장하기 어렵다.
- 다른 방법과의 정량 비교가 없다. audio-to-motion이나 motion-to-motion에서 학습 기반 방법(WalkTheDog 등)과 비교하면 품질이 어느 정도일까?
- topic을 "Motion matching"으로 분류했지만, 실제 방법은 OT 기반 temporal alignment/motion control에 더 가깝다. 분류를 다시 볼 필요가 있을 수 있다.
- d_X, d_Y를 어떤 feature 공간에서 정의하느냐(예: 오디오 MFCC)에 결과가 크게 좌우될 것 같은데, 그 민감도는 보고되지 않았다.
